# Tests

Nova's automated checks. All tests use Python 3 standard library `unittest` plus the vendored YAML parser (`system/tools/vendor/`); nothing needs installing. Run them from the repository root. They must all pass before a release (`system/tools/build-zip.md`) and after every update (`nova-update`, `nova-health`).

**Everything at once:**
```
python3 -m unittest discover -s system/tests -t system/tests
```

## Hook and validator tests

### What they cover
| Folder | Covers | Build plan |
|---|---|---|
| `hooks/` | `.claude/hooks/actions.py` (N1-N4), `paths.py` (N5, N6), `git.py` (N8, N10, N12), the upstream bypass and context detection in `context.py`, `failsafe.py`, and the sync hooks `sync_start.py` (SessionStart) and `sync_guard.py` (Stop) in `test_sync.py` | T-1 (H-1..H-6) |
| `validators/` | `system/tools/validate.py`: record frontmatter, settings files, registry, manifest, VERSION, skills, jobs, profiles, dashboard contracts, migrations, settings templates; plus a check that this repository itself validates | T-2 |

### How to run
```
python3 -m unittest discover -s system/tests/hooks -v        # hook tests
python3 -m unittest discover -s system/tests/validators -v   # validator tests
python3 system/tools/validate.py --all                       # validate this repo
```
`validate.py` options: `--system`, `--user`, `--all` (default), `--root DIR` (validate another checkout), `--quiet` (errors only), or a list of file paths. It exits 1 when there is any ERROR. Folders that have no files yet produce warnings; once a folder has files, every expected component (20 skills, 12 jobs, dashboard contracts, settings templates) must exist.

### How the hook tests work
Each test builds a throwaway git repo in a temp folder that looks like a **user's** Nova repo (origin set to a non-upstream URL, hooks, manifest and vendored parser copied in), then runs a hook script exactly as Claude Code does: one JSON object on stdin (`tool_name`, `tool_input`, `cwd`, ...), `CLAUDE_PROJECT_DIR` pointing at the temp repo, and `NOVA_CONTEXT` set to `routine` (any case), `chat`, another value, empty, or left unset. A block is exit code 2 with the reason on stderr; "ask the user" is exit 0 with a JSON `permissionDecision: "ask"`.

Fake secrets in `hooks/test_git.py` are assembled at runtime so no committed file contains a secret-shaped string (the commit hook would flag it). Keep it that way in any new test or doc.

Cases covered include: send in routine (block), send in chat without a record (block), with a record (allow once; record consumed), expired or over-long record (block), record for another tool or action (block), security/financial tools (always block), unmapped tool with an unclear name (block in routine, ask in chat), Bash deletes under `user/` (block without a `destructive` record), owned-path writes with and without the update lock, governance files in routine (block) and chat (record with `governance_settings`), approval records and purge locks can't be created in routines, force push and history rewrites (block), the purge-lock exception (chat only), commits without `Nova-Actor`/`Nova-Reason` trailers (block), secrets in staged or same-command changes (block), the upstream bypass in all remote URL forms (allow everything), session-start pull (new remote commits arrive, local edits survive, failures and conflicts reported without crashing), Stop blocking on uncommitted, untracked or unpushed work but not on ignored paths, the loop-safety release (`stop_hook_active`, 3rd block, per-session counter, safe health.yaml update), `NOVA_CONTEXT=routine` matched case-insensitively, and a missing, empty or other `NOVA_CONTEXT` treated as chat (locked actions still need an approval record).

### Hook design notes and known limits
- **Sync hooks** (`system/rules/sync.md`): `sync_start.py` (SessionStart, sources `startup|resume|clear`) runs `git fetch` and `git pull --rebase --autostash origin main` (about 20 s) and tells Claude "Nova repo synced to origin/main at <sha>"; on any failure (network, auth, conflict, not on `main`) it aborts a half-done rebase, logs to `.nova-tmp/sync.log`, and tells Claude to retry the pull before touching Nova files. It never blocks. `sync_guard.py` (Stop) blocks the end of a turn (`decision: block`) while tracked files have uncommitted changes, untracked non-ignored files exist (except `.nova-tmp/` and `user/inbox/drop/`), a rebase/merge is unfinished, or HEAD has commits `origin/main` lacks (after a quick fetch). Loop safety: when `stop_hook_active` is true or on the 3rd consecutive block in a session (`.nova-tmp/sync_guard.json`), it lets the turn end, adds a high-severity `sync-push-failing` known issue to `user/.state/health.yaml` when that file exists and can be edited safely, and shows the user a one-line warning (`systemMessage`). It fails open on internal errors. Both are no-ops in the upstream repo. Tests use a local bare repo as `origin` (outside the work tree) and a second clone to push "remote" commits.
- **Context:** routines are identified by a marker. `NOVA_CONTEXT=routine` (case-insensitive, trimmed) means routine; anything else (missing, empty, `chat`, other values) means chat. Claude Code routines run in cloud environments that set the variable reliably; the chat surfaces users work in can't. Chat is still guarded: every locked action needs a single-use approval record, so an unmarked session can't take a locked action without an explicit, recorded confirmation. Routines block N1-N4 outright, can't change governance files (except first creation), can't create approval records or purge locks, and can't commit as `Nova-Actor: chat`.
- **Upstream bypass:** every hook is a no-op when `git remote get-url origin` names the repo in `system/manifest.yaml: upstream` (https, ssh, scp-style, `.git` suffix and proxy URLs all compare by their last `owner/repo`, case-insensitively). This is how maintainers develop Nova. A missing manifest does not switch hooks off: the bypass falls back to `CaptLocke/nova` and owned paths to a built-in copy of the manifest list. `git.py` blocks changing `origin` in user repos so the bypass can't be switched on from inside a session.
- **Fail closed:** hooks catch their own errors (Claude Code treats any exit code other than 0 or 2 as a non-blocking error). On an internal error they block in routines and for locked actions, and allow with a warning otherwise. If a hook can't even import its modules, `failsafe.py` (standard library only) decides: allow in the upstream repo, block in routine context, and otherwise (chat, including a missing marker) allow only clearly harmless calls (read-named MCP tools, writes under `user/` other than governance files, shell commands with no risky word). `.claude/settings.json` also sets `"onFailure": "block"` (a documented command-hook field, Claude Code v2.1.295+) so a hook that can't start or times out blocks the call.
- **Risk classification** (`actions.py`): the `tool_risk` tag from `user/settings/connectors.yaml` (matched by `mcp_prefix` or any of `mcp_prefixes`, case-insensitively, falling back to the MCP server name vs. the connector name ignoring case, `-`, `_` and spaces) plus name patterns from `system/connectors/README.md` and a few additions (`comment`, `accept`, `decline` = send; `cancel` = delete), matched on whole name tokens with simple inflections (`design` is not `sign`). The riskiest wins. Refinements: a name whose first verb (after any vendor prefix) is a read verb and has no later unambiguous action verb is a read, so send/share/delete/money nouns don't count (`slack_get_thread_replies`, `list_shared_drives`, `list_payments`); credential words still do (`get_password`). A create verb plus a message noun is a send (`chat_message_create`, `create_post`). A draft with `reply`/`forward` but no `send`/`post`/`publish` is a draft (`create_reply_draft`). Creating or changing a calendar event is a send unless the tool is tagged `write` and the call has no attendees/invitees/guests/participants.
- **Approval records:** must name the exact `tool`, an `action` matching the call's class, a non-empty `user_confirmation`, and expire within 2 minutes (update lock 30, purge lock 15; one minute of clock slack). A record that claims a longer life is rejected. For governance files the `target` must be the file's repo-relative path (absolute and `./` forms are normalized). Creating a governance file that doesn't exist yet (setup copying defaults) is allowed in any context without a record, and a leftover record naming that path is deleted.
- **Git refs and repo settings:** deleting tags needs the update lock (or a purge lock in chat); deleting branches that exist on origin needs a purge lock in chat. `gh repo edit --visibility` and non-GET `gh api` calls touching collaborators, invitations or visibility are always blocked (N9). Commits with `Nova-Actor: setup` are allowed in any context; `Nova-Actor: chat` in a session marked as a routine is blocked, with a pointer to `Nova-Actor: routine:<routine-name>`.
- **Exempt deletes:** `user/inbox/drop/` (staging copies removed after filing) and `user/knowledge/_index/` (regenerable) can be deleted without approval.
- **Shell analysis is pragmatic** (`.claude/hooks/shell.py`): it understands separators, `cd`, `VAR=` prefixes, wrappers (`sudo`, `env`, `timeout`...), `bash -c`/`eval`, redirections, heredocs, `tee`, `sed -i`, `cp`/`mv`/`install`/`rsync`/`ln`, `rm`/`unlink`/`shred`, `find -delete`, `touch`/`mkdir`/`chmod`, `dd of=`, `unzip`/`tar -x`, and `git rm/mv/checkout --/restore/clean -f`. It does **not** expand variables or command substitutions, reduces globs to their literal prefix, and cannot see writes made by interpreters (`python -c`, `node -e`, `awk` redirection inside its program). These are procedural guards backed by the rules and the health-check audits, not a sandbox.
- **Commit messages:** read from `-m`, `--message`, `-F <file>`, `-F -` with a heredoc, and `-m "$(cat <<EOF ...)"`. When the source can't be read (editor, `-C`, `--amend` without `-m`), the commit is allowed with a warning.
- **Secret scan:** added lines of `git diff --cached`; when the same command runs `git add` or `commit -a`, also unstaged changes and untracked files (text files up to 2 MB).
